# COLD CASE

A narrative cold-case investigation game in Unreal Engine 5. The game knows the truth; the player does not.

This repository currently holds the **Till Roll** prototype: a mechanics test, not Case 001 canon.

## What's in here

```
ColdCase.uproject                 the project file (double-click to open in Unreal)
Config/                           project settings (text .ini files)
Source/ColdCase/                  thin game module: game mode, startup
Plugins/
  InvestigationFramework/         all investigation systems in C++. Knows nothing about any specific case.
    Source/InvestigationRuntime/
  Cases/
    Case000_TillRoll/             the test case
      CaseData/Case.json          everything the player can reach: questions, people, exhibits
      CaseData/Truth.json         what really happened. Only read after the case is concluded, or by tools.
```

Folders you will see appear after building (`Binaries`, `Intermediate`, `Saved`, `DerivedDataCache`) are generated by Unreal and are deliberately not stored in Git.

## One-time setup on your PC

1. **Unreal Engine 5.7** (5.7.1 or later) from the Epic Games Launcher (Unreal Engine > Library > + next to Engine Versions).
2. **Visual Studio 2026 Community.** In the installer, tick the **Game development with C++** workload, and on the right make sure **Unreal Engine installer**, **MSVC (latest)** and a **Windows 11 SDK** are ticked.
3. **Git for Windows** (includes Git LFS) and **GitHub Desktop**.
4. Open a terminal (Start > "Git Bash") and run once: `git lfs install`

## Getting the project and building it

1. In GitHub Desktop: **File > Clone repository**, pick `cold-case`, and set the local path to `C:\Dev\ColdCase`.
2. Switch to the branch you were sent (GitHub Desktop: **Current branch** drop-down).
3. In File Explorer, right-click `ColdCase.uproject` > **Show more options** > **Generate Visual Studio project files**. A `ColdCase.sln` file appears.
4. Double-click `ColdCase.sln` to open it in Visual Studio.
5. In the toolbar, check the two drop-downs say **Development Editor** and **Win64**.
6. **Build > Build Solution** (Ctrl+Shift+B). The first build takes several minutes.
   - If it fails, open **View > Error List**, and send the **first** error (the top one is usually the real cause).
7. When it says `Build succeeded`, close Visual Studio and double-click `ColdCase.uproject`.

## Checking it works (Milestone 1)

1. In the editor, press **Play** (the green triangle, or Alt+P).
2. Green text should appear top-left: `Case loaded: Case 000: The Till Roll`.
3. Press the **`** key (left of 1) to open the console, type `ColdCase.DumpCase` and press Enter.
4. Open **Window > Output Log**, type `LogInvestigation` in its search box. You should see the case's questions, four people and five exhibits.
5. In the console, type `ColdCase.ValidateCase`. The log should end with `Validation finished: 0 problem(s).`

## Checking the case file (Milestone 2)

Press Play, open the console with **`**, and keep **Window > Output Log** open filtered to `LogInvestigation`.

1. `ColdCase.CaseFile` lists the four exhibits from the original file, all "not examined".
2. `ColdCase.Examine TillRoll.E.TillRoll`, then `ColdCase.CaseFile` again: the till roll's finding and its two readings appear, neither chosen.
3. `ColdCase.Interpret TillRoll.E.TillRoll.LastSale TillRoll.E.TillRoll.LastSale.SarahWorking`: the case file now says your exhibits point to "After 23:30". Nothing tells you whether that reading is right.
4. `ColdCase.Request TillRoll.E.DVLARecord`: it shows as requested, not arrived.
5. The DVLA record arrives once you finish your next interview (see Milestone 3).

## Checking interviews (Milestone 3)

There are no dialogue trees. You pick a topic to ask about or an exhibit to show, and optionally add `rapport` or `challenge`. What the person says depends on how much they trust you, how composed they are, and what you've already put to them. Nothing ever tells you whether an answer is true.

`ColdCase.Topics` lists the people and topic IDs. A good first run:

1. `ColdCase.Request TillRoll.E.DVLARecord`
2. `ColdCase.Interview TillRoll.C.Lorraine`
3. `ColdCase.Ask TillRoll.T.LastShift` : she is certain Sarah left about eleven.
4. `ColdCase.Present TillRoll.E.TillRoll` : she is shaken, and has nothing to defend.
5. `ColdCase.Ask TillRoll.T.LastShift` again: her account has changed, and she is no longer sure.
6. `ColdCase.EndInterview` : the DVLA record arrives.
7. `ColdCase.Interview TillRoll.C.Mick`, then try `ColdCase.Ask TillRoll.T.LastShift`, `ColdCase.Present TillRoll.E.TillRoll`, `ColdCase.Present TillRoll.E.DVLARecord`, and `ColdCase.Present TillRoll.E.NeighbourStatement2000 challenge` more than once. He gives ground a step at a time, and only when pushed with evidence.
8. `ColdCase.CaseFile` : every statement that asserted something is listed under "Statements taken".

Things to try on a fresh Play: challenge Mick about the car (`ColdCase.Ask TillRoll.T.Car challenge`) before the DVLA record has arrived. He stops cooperating for good, and Lorraine has something new to say about him afterwards.

`ColdCase.Debug.People` (development builds only) shows the hidden trust, composure and story step, for checking the rules. The finished game never shows these.

## Working rules

- C++ owns rules and state, case data owns content, Blueprints own presentation.
- The framework never mentions a specific case. Anything a case needs becomes a general feature.
- Systems that run during play never read `Truth.json`. Correctness is never shown during play; it appears only in the case-review report after the player concludes.
- IDs such as `TillRoll.F.SarahLeftAt.After2330` are permanent. Saves refer to them, so don't rename them casually.
